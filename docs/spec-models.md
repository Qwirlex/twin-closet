## Что есть сейчас

- Клиент Meta (`server/src/meta.ts`): Responses, загрузка файлов, повторы при 429/503, разбор текста/цитат/картинок.
- Промпты и строгие схемы Muse Spark (`models/spark.ts`), подсказки и разбор SAM 3.1 официальным парсером (`models/sam.ts`),
  запросы примерки Muse Image (`models/image.ts`), склейка примерки с защитой лица и рук (`tryon/compose.ts`), Twin (`models/twin.ts`).
- В задачах вызывается только поиск в магазине. Все остальные шаги моделей (`server/src/jobs.ts → modelStep`)
  кончаются ошибкой «not connected to the Meta models yet»; при пустом ключе — честное «ждёт ключ».
- Приложение: скан и вещь ждут результат задачи (`result.garments`, `result.item`, `result.body`), примерка и Twin
  показывают заготовки демо-аккаунта.

## Что делаем

Каждый шаг — отдельная функция в `server/src/pipeline/` с одним входом и выходом; `jobs.ts` только раскладывает шаги.
Без ключа всё по-прежнему останавливается на первом шаге модели с «ждёт ключ» — поведение для судей не меняется.

### A. Общее (`pipeline/common.ts`)
- `imagePart(path)` — файл → `input_image` (data: URL JPEG, кадры уже ≤ 1280 px).
- `remoteImage(url)` — картинка по ссылке **только из своих мест**: `/files/…` этого сервера (локальный файл) и сайт
  приложения (`https://twin-closet.vercel.app/assets/…`, демо-фото); всё остальное — отказ (никаких запросов на чужие адреса).
- `runSam(meta, prompt, media)` — запрос + `parseSam`; 0 объектов — пустой список, не ошибка.
- `bestObject(objects)` — самый уверенный и крупный; `cutout(frame, mask, out)` — PNG с прозрачностью, обрезка по маске с полями.
- `objectMask(object, w, h)` — маска во весь кадр (`samMask`), без растра — прямоугольник рамки.

### B. Новая вещь (`import_item`) — главный путь судьи: скриншот → вырезка → что это → в магазине → «уже есть»
Шаги в новом порядке (подпись модели у каждого прежняя):
1. **read** (Muse Spark, `readTag`): по всем снимкам (перед, спина, ярлык, бирка) — бренд, название, вид, цвет, REF, цены, размер, состав.
2. **cutout** (SAM 3.1): понятие = короткое название вещи от Spark (`"wide-leg jeans"`, иначе вид: `"jeans"`), лучший объект
   → `/files/<job>-cut.png`. Ничего не нашлось — вырезкой остаётся само фото (вещь не теряется), в результате пометка.
3. **online** (Muse Spark + веб-поиск): если бренд — живой магазин и есть REF или название → `findProduct`; первая страница
   этого магазина → ссылка и цена. Иначе шаг проходит без поиска.
4. **similar** (Muse Spark, `findSimilar`): со шкафом из входа задачи (`closet`: id, название, вид, цвет — приложение шлёт
   свой шкаф вместе с задачей) → `result.similar`. Пустой шкаф — шаг без вызова.
Итог — `result.item: Garment` (вырезка, подпись, магазин, цена, REF, размер, состав).

### C. Скан шкафа (`closet_scan`)
1. **detect** (Spark, `detectGarments`): ключевые кадры по номерам → вещи с рамками 0–1000 и лучшим кадром.
2. **track** (SAM 3.1, видео): видео загружается в Files API → рамки в пикселях на кадре видео этого ключевого кадра
   (номер кадра = время ключевого кадра × fps) → трек; больше 16 вещей — группами по 16.
3. **cutout** (SAM 3.1): для каждой вещи кадр с самой большой маской, не обрезанной краем → кадр из видео (ffmpeg) → PNG.
4. **tag** (Spark): `tagGarment` по каждой вырезке, затем `dedupeGarments` — одна вещь, снятая дважды, остаётся одной.
Итог — `result.garments`.

### D. Скан себя (`body_scan`)
1. **angles** (Spark, `pickAngles`) — как было; у умного скана ракурсы уже подписаны и шаг пропускается.
2. **masks** (SAM 3.1, понятия по одному на запрос): `person`, `face`, `hair`, `hand` и одежда (`top`, `pants`, `shoes`,
   `jacket`, `dress`) на каждом ракурсе → PNG масок; защищённая зона = лицо ∪ волосы ∪ кисти.
Итог — `result.body: BodyPhoto[]`; советы Spark («отойди, чтобы ступни были в кадре») — `result.problems`.

### E. Примерка (`try_on`)
Новый вход задачи `{ tryOn: { person, garments: [{ label, url, fit? }], angle } }`, ссылки — только свои (A).
1. **dress** (Muse Image): `tryOnRequest`, поиск выключен → картинка.
2. **protect** (SAM 3.1): маски человека, защищённой зоны и меняемой одежды на оригинале и на генерации → `composeTryOn`
   (выравнивание, вклейка лица и рук из оригинала). Поза уехала — честная ошибка «try again», не кривой результат.
3. **check** (Spark, `checkTryOn`): та же ли это персона, поза, похожа ли вещь, нет ли шва → `score` и `issue`.
Итог — `result.render: { angle, url, score, issue }`.
Приложение: во вкладке Try on, когда у сервера есть ключ и есть свои разобранные вещи (вырезки с сервера), — карточка
«On you, for real» с кнопкой «Render on me · Muse Image»: фото демо-человека (ассет сайта) + вырезки → шаги задачи → рендер
и оценка Spark. Не на экране образа: образы пока строятся только из демо-вещей, своих вещей в них нет (подключим /looks с ключом).
Только на сайте: в приложении фото — локальные файлы, сервер их не получит без загрузки (сделаем, если понадобится).

### F. Twin (`POST /twin`)
- Вход: история чата и контекст из приложения (шкаф, вишлист, стиль, любимые магазины, страна).
- Сервер крутит цикл Muse Spark с инструментами (до 6 вызовов): `get_closet`, `get_wishlist`, `get_style`, `get_trends`,
  `get_stores` — из контекста; `search_store` — `findProduct` по живому магазину; `add_to_wishlist` и `start_try_on` —
  не выполняются на сервере, а возвращаются приложению действиями (кнопки «Save» и «Try it on»).
- Ответ: текст, действия, id ответа для продолжения. Без ключа — 503 с понятным текстом; приложение тогда отвечает
  заготовками, как сейчас.

### G. Образы (`POST /looks`)
- Новые вещи + шкаф + стиль + страна → `buildLooks` с `looksBrief` (стиль и тренды) → `markPlain`: скучная база — последней.
- Сейчас без вызова из приложения (демо-образы остаются); подключим к экрану примерки, когда увидим живой ответ.
