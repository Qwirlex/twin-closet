# Meta Models Wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every model step of import_item, closet_scan, body_scan and try_on runs real SAM 3.1 / Muse Spark / Muse Image calls, plus Twin with tools and outfit building, all proven on a fake Meta API (spec: `docs/spec-models.md`).

**Architecture:** `server/src/pipeline/` holds one module per job (`common.ts`, `item.ts`, `closet.ts`, `body.ts`, `tryon.ts`) and `twin.ts`/`looks.ts` for the chat loop and outfits. `jobs.ts` keeps step bookkeeping and delegates `modelStep` to them. Tests drive everything through `MetaApi` with a fake `fetch` (`test/fake-meta.ts`) that answers by model and Spark task name.

**Tech Stack:** TypeScript, Hono, sharp, ffmpeg, `@meta-sam/parser`, vitest.

---

### Task 1: Fake Meta API + common helpers
- Create `server/test/fake-meta.ts`: `fakeMeta({ spark: { [taskName]: json | (body) => json }, sam: (prompt) => text, image: () => base64 })` → `{ meta, calls }`; Files API returns `{ id: 'file-1' }`.
- Create `server/src/pipeline/common.ts`: `imagePart`, `remoteImage` (own `/files/` and app assets only), `runSam`, `bestObject`, `objectMask`, `cutout`.
- Tests `server/test/pipeline.test.ts`: cutout of the README SAM sample on a 320×334 image has alpha only inside the mask; `remoteImage('https://evil.example/x.jpg')` rejects.

### Task 2: import_item
- New step order read → cutout → online → similar in `jobs.ts`; `JobInput` gets optional `closet` for import_item; route accepts it.
- `pipeline/item.ts`: `readItem`, `cutItem`, `findOnline`, `similarOwned` filling `result.item` / `result.similar`.
- Tests: screenshot → item with cutout PNG, brand Zara + REF → product link and price, closet → similar; SAM finds nothing → photo kept as cutout; no key → `no_key` at read.

### Task 3: closet_scan
- `pipeline/closet.ts`: `detect` (Spark), `track` (upload + SAM video with boxes, groups of 16), `cutouts` (best frame per id via ffmpeg `frameAt`), `tag` (tagGarment + dedupe) → `result.garments`.
- Test on a 2-second generated video: two garments, duplicates merged.

### Task 4: body_scan
- `pipeline/body.ts`: `angles` (Spark pickAngles → frames), `masks` (SAM concepts per angle, 3 at a time) → `result.body`, `result.problems`.
- Test: 4 angles from keyframes, protected mask = face ∪ hair ∪ hand saved as PNG.

### Task 5: try_on
- `JobInput` `{ tryOn }`, `pipeline/tryon.ts`: `dress` (Muse Image), `protect` (SAM + composeTryOn), `check` (Spark) → `result.render`.
- Test: render saved and accepted; foreign URL rejected; check score kept.
- App: Result screen "Render on me · Muse Image" when `/health` says meta live and the look has no render.

### Task 6: Twin + looks
- `pipeline/twin.ts` loop over `function_call` items (max 6), tools from context; `POST /twin`. `pipeline/looks.ts` + `POST /looks`.
- App `twin.tsx`: live server → `/twin`, actions as buttons; else canned replies.
- Tests: tool call → result → final text; add_to_wishlist returned as action; no key → 503; looks marked plain last.

### Task 7: Verify and commit
- `npm test -w @twin/server`, `npm run typecheck`, browser: without the key everything behaves as before.
