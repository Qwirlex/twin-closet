# Спека: версия для судей (день 8, без ключа)

План — PLAN.md, разделы 1.3 и 6. Пользователь 29.10: «без ключа делай по порядку всё, спека → план → реализация, с проверкой».

## Что уже есть (проверено 29.10 на https://twin-closet.vercel.app с ноутбука 1366×768)

- Сайт = приложение, демо-аккаунт, сервер на Render (`/health` → `meta: false`, ключа нет), QR «Scan with your phone»,
  лимиты загрузок и задач, README со схемой моделей.
- Путь судьи сейчас: гайд (3 экрана, можно Skip) → вход → **замеры** → **опрос стиля** → Шкаф. До главного шага
  (Try on → скриншот) — пять экранов, два из них анкеты, которые судье не нужны.
- На ноутбуке приложение — колонка 440 px посередине, по бокам пусто. Судья не видит, что попробовать и какая
  модель Meta что делает (а это 25% оценки), пока не откроет README.
- README не знает о сделанном 28–29.10: посадка по зонам и замеры, опрос стиля (59 стилей), умный скан с позой
  на устройстве, вишлист и скидки, список магазинов.

## Цель

Судья с ноутбука за 2 минуты: видит примерку на демо-человеке, кидает свой скриншот, понимает, какая модель Meta
делает каждый шаг и что работает прямо сейчас.

## 1. Вход в демо-аккаунт — сразу к делу

- «Explore the demo account» → сразу вкладка **Try on** (главный шаг судьи: «кинь скриншот»).
- Демо-аккаунт — готовый человек: замеры уже есть (`DEMO_BODY`), и появляется **демо-профиль стиля**
  `DEMO_STYLE` = результат опроса «’90s minimal — love, Military surplus — like, Scandi minimal — like»
  (считается той же `profileFromVotes`, что и настоящий опрос). Под него собраны демо-образы, поэтому
  на примерке сразу «In your style · …», а не «Take the style quiz».
- Профиль ставится, только если своего ещё нет (`style === null`): кто прошёл опрос — его ответы не трогаем.
- Вторая кнопка под главной: **«Set up my measurements and style»** → прежний путь (замеры → опрос → Шкаф).
  Анкеты не пропадают: так их хотел пользователь (PLAN.md §1.2 А, Е), просто не стоят на пути судьи.
- Повторный вход (гайд «Show the intro again» в Me) ведёт так же.

## 2. Панель судьи рядом с приложением (только сайт на компьютере)

Показывается, когда сайт открыт мышью (`isDesktopWeb()`) и окно шире **1100 px**. На телефоне, планшете и в приложении
её нет. Панель слева от колонки приложения, пара «панель + колонка» по центру окна. Ширина панели 360 px,
прокрутка своя, стиль Noir (те же токены и шрифт, тёмная и светлая тема).

Содержимое сверху вниз:
1. **Twin Closet · for judges** и одна строка: «See any piece on your real body, styled with what you already own».
2. **Статус моделей** (из `GET /health` сервера, раз в минуту):
   - `meta: true` → «Meta models are live»;
   - `meta: false` → «Waiting for the hackathon API key — steps that need a model say so on screen»;
   - нет ответа → «Server is waking up…» и повтор.
3. **Try this** — 4 шага, каждый кнопкой (открывает экран в колонке рядом):
   1. *Drop a screenshot from any store* → Try on (там же можно перетащить файл на страницу);
   2. *See it on you, then tap Fit* → Result: примерка, ракурсы, посадка по зонам;
   3. *Scan with your phone* → Scan: QR, снимаешь телефоном — шаги идут здесь;
   4. *Your style and measurements* → Me.
4. **Meta models in this demo** — короткая карта «шаг → модель» (SAM 3.1, Muse Spark, Muse Image,
   Muse Voice Transcribe) из того же списка, что в README. Отдельной строкой честно: поза в скане себя считается
   на устройстве (MediaPipe), это не модель Meta.
5. **Continue on your phone** — кнопка открывает в колонке готовый экран `/connect` (QR с тем же id устройства и живые
   обновления с телефона), подпись «nothing to install». Свой QR в панели не рисуем: экран `/connect` уже включает
   частую синхронизацию, пока открыт, — дублировать эту логику незачем.
6. Ссылки: **How it works (README)** и **Source code** — GitHub.

Данные карты моделей и шагов — один модуль (`app/src/data/judges.ts`), README и панель не расходятся по смыслу.

## 3. README

- «Try it as a judge»: новый вход (сразу Try on), панель на ноутбуке, что попробовать.
- «What each Meta model does»: добавить посадку (Spark читает таблицу замеров со страницы и состав), стиль по своим
  фото (Spark), умный скан (поза на устройстве, MediaPipe — не Meta; маски и вырезка — SAM 3.1).
- Новый раздел **«Built without the key, working now»**: посадка по зонам и сравнение с любимой вещью, замеры,
  опрос стиля на 59 стилей и профиль, умный скан (поза, свет, неподвижность, автоснимки), вишлист и скидки,
  магазины по странам. Коротко, по строке на фичу.
- «Status»: что ждёт ключ — честно и коротко.
- Mermaid: магазины не только Zara / Bershka / Pull & Bear (общая подпись «store pages, Muse Spark web search»).

## Проверка

- `DEMO_STYLE` живёт в `packages/shared/src/style.ts` (рядом с опросом). Тест (`server/test/style.test.ts`):
  проходит `cleanStyle` без изменений, ровно три стиля — ’90s minimal 50%, Scandi minimal и Military surplus по 25% (равные — в порядке опроса) — с долями
  по убыванию, и каждый из четырёх демо-образов (их стили перечислены в тесте) получает `styleMatch > 0`.
- В браузере на собранном сайте: 1366×768 и 1920×1080 — панель видна, 4 кнопки открывают нужные экраны,
  у каждого демо-образа на примерке «In your style · …»,
  статус «Waiting for the hackathon API key»; 390×844 (телефон) и 1024×768 — панели нет;
  вход демо → Try on; на примерке «In your style · …»; «Set up my measurements and style» → замеры → опрос.
- `npm run typecheck`, все тесты сервера.
