# Спека: любимые магазины, вишлист, скидки

План — PLAN.md, раздел 1.1. Подтверждено пользователем 27.10 (план и спека — сразу).

## Цель

Человек отмечает свои магазины и складывает вещи в вишлист. Twin собирает образы из шкафа и вишлиста,
ищет недостающее в любимых магазинах, а приложение говорит, когда вещь из вишлиста подешевела.

## Что в первой версии (к хакатону)

- **Работают по-настоящему три магазина: Zara, Bershka, Pull & Bear** (их назвал пользователь; у всех трёх
  одинаковая бирка с артикулом REF). Для них — поиск вещи онлайн, цена, ссылка и слежка за ценой.
- **Остальные популярные бренды** есть в списке, их можно отметить любимыми, но у них метка **Coming soon**,
  а внизу списка — **Other shops coming soon**. Поиск и слежка за ценой для них выключены.
- Пуш-уведомления о скидках — потом. Сейчас скидка видна в вишлисте (бейдж и старая цена зачёркнута).

## Откуда данные (и чего не делаем)

1. **Список брендов** — Name Suggestion Index (OpenStreetMap, BSD-3): 60 популярных брендов одежды с Wikidata
   и странами + официальные сайты (вписаны вручную). Файл `app/src/data/stores.ts`, источник указан в README.
   Страны у мировых брендов в наборе — «весь мир», у региональных — список стран. Поэтому регион только
   сортирует («сначала магазины твоей страны»), ничего не прячет.
2. **Данные вещи** — только из двух мест:
   - **фото самого человека**: SAM 3.1 вырезает вещь, Muse Spark читает бирку (бренд, REF, цена, размер, состав);
   - **веб-поиск Muse Spark** (`web_search`, Responses API) по сайту магазина + `user_location`:
     находит ту же вещь онлайн по REF или описанию — ссылка, название, цена из найденного текста.
3. **Не обращаемся к сайтам и внутренним API магазинов напрямую** — их правила запрещают сбор данных роботами,
   а сайты закрыты защитой от ботов. Это решение, а не временное ограничение.
4. Картинка вещи — вырезка из фото человека. У результатов поиска Twin картинки может не быть: показываем
   карточку-ссылку «Open in Zara»; вещь с картинкой появляется, когда человек сохраняет её скриншотом.
   С ключом проверить: отдаёт ли `web_search` картинки и работает ли `allowed_domains`.

## Экраны

- **Me › My stores** → экран «Stores»: выбор страны (по умолчанию — регион телефона), поиск по брендам,
  разделы «In your country» и «Worldwide», у каждого бренда — монограмма, название, сайт, метка
  Live / Coming soon и переключатель «любимый». Внизу — «Other shops coming soon».
- **Closet › Wishlist** (сегмент рядом с «My closet»): карточки вещей — фото, название, магазин, цена;
  при скидке — бейдж «−20%» и старая цена зачёркнута; сверху баннер «N price drops».
  Пустое состояние объясняет, как добавить. Кнопки на карточке: убрать, примерить.
- **Сердечко** у вещей в «Try on» — добавить в вишлист / убрать.
- **Twin**: подсказка «Find it in Zara»; без ключа — честный ответ, что поиск включится с ключом.

## Сервер

- Новая задача `product_lookup` — шаги: «Searching {store}» (Muse Spark web search), «Reading price and sizes»
  (Muse Spark). Вход: `{ store, query | ref, country }`. Результат: `products: ProductHit[]`.
- В `import_item` новый шаг после чтения бирки: **«Finding it online»** (Muse Spark web search).
- **Слежка за ценой**: `PUT /watch` — приложение присылает вишлист (только вещи живых магазинов с REF или ссылкой);
  `GET /watch` — те же вещи с последней ценой, `onSale`, `checkedAt`. Раз в 24 часа (и через минуту после запуска)
  сервер проверяет цены через `product_lookup`. Без ключа проверка пропускается с записью в лог,
  у вещей `checkedAt` остаётся пустым.
- Хранение — тот же `server/data/db.json`.

## Типы (`packages/shared`)

- `StoreBrand { id, name, domain, wikidata, countries: string[] ('001' = весь мир), live: boolean }`
- `WishItem { id, name, storeId | null, ref | null, url | null, image, price | null, currency | null, addedAt }`
- `WatchItem extends WishItem { lastPrice, onSale, checkedAt }`
- `ProductHit { title, url, price | null, currency | null, snippet }`

## Готово, когда

- Тесты сервера: сохранение и чтение `/watch`; `product_lookup` и шаг «Finding it online» без ключа останавливаются
  с `no_key`; вещи не из живых магазинов не попадают в проверку цен.
- В браузере: выбрать страну, отметить Zara и Mango (Mango — Coming soon), добавить вещь в вишлист сердечком,
  увидеть её в Closet › Wishlist; бейдж скидки показывается, когда `onSale` (проверить на тестовых данных сервера).
- Типы и тесты зелёные, коммит.

## Скидки v2 — как сделать надёжно и дёшево (предложение 27.10)

Сейчас: раз в сутки по каждой вещи один поиск Muse Spark, скидка = цена ниже, чем при добавлении.
Этого мало: поиск может ошибиться, а проверять каждую вещь каждый день — дорого, когда людей много.

### 1. Откуда узнаём о скидке (только разрешённые пути)

| Сигнал | Как | Когда |
|---|---|---|
| **«Сейчас распродажа?»** по магазину | один поиск Spark на магазин и страну в день: «Is the Zara sale on in Ireland right now?» → да/нет + ссылка на источник | каждый день, 3 магазина × страны пользователей — копейки |
| **Цена вещи** | поиск Spark по REF/названию на сайте магазина → цена из найденной страницы | ежедневно **только в режиме распродажи**, вне её — раз в неделю |
| **Бирка в магазине** | Spark читает обе цены на ценнике со скидкой (старая зачёркнута, новая) | когда человек сканирует вещь |
| **Известные сезоны** | зимняя (с конца декабря), летняя (с конца июня), Black Friday — заранее включаем ежедневную проверку | календарь, сверяем тем же поиском «сейчас распродажа?» |

Режим распродажи экономит почти все проверки: 11 месяцев в году вещи проверяются раз в неделю, в распродажу — каждый день.

### 2. Когда считаем, что скидка настоящая

- Цена из **страницы того же магазина** (ссылка в цитате Spark на домен магазина) и **та же страна и валюта**.
- Совпадает REF или название + цвет; иначе — «похожая вещь дешевле», а не «твоя вещь подешевела».
- **Две проверки подряд** показывают одну цену (вторая — сразу, через час) — только тогда показываем.
- Рядом всегда «проверено 2 ч назад · источник» — человек сам открывает страницу.

### 3. Что видит человек

- **История цены** у каждой вещи: точки проверок, «самая низкая за 30 дней».
- **Своя цель:** «скажи, когда будет дешевле €30» — уведомление только при достижении.
- **Бейдж и баннер** в вишлисте (уже есть), плюс на образе: «этот образ сейчас на €18 дешевле — джинсы со скидкой».
- **Twin раз в неделю:** «В вишлисте 2 вещи подешевели; в Zara распродажа с пятницы — подождать с курткой?»
- **Уведомления:** в приложении — сразу; пуш на телефон — через dev-сборку Expo (в Expo Go на Android пушей нет).
  Локальное уведомление «пока тебя не было, подешевели 2 вещи» при открытии — работает и в Expo Go.

### 4. Сервер

- `price_history` в `db.json`: `{ itemId, price, currency, url, source, checkedAt }` — каждая проверка.
- `store_sales`: `{ storeId, country, onSale, source, checkedAt }` — ежедневный ответ «распродажа?».
- Планировщик: раз в сутки — `store_sales` для пар «магазин × страна» из вишлистов; затем цены:
  ежедневно, если `onSale` или до сезона < 3 дней; иначе — если с прошлой проверки ≥ 7 дней.
- Подтверждение скидки — повторная проверка через час, `onSale` = обе проверки ниже цены добавления
  (или ниже цели человека).
- Стоимость: один поиск Spark ≈ несколько тысяч токенов ≈ доля цента; 3 магазина × 10 стран в день ≈ ничего.

### 5. Порядок работ

Без ключа (можно сразу): история цены и цель в данных и на экране вещи, режим распродажи в планировщике,
подтверждение двумя проверками, бейдж на образе, локальное уведомление при открытии, тесты на логику.
С ключом: сами запросы Spark — «распродажа?», цена по REF, чтение ценника со скидкой; проверить качество на 10 вещах.
