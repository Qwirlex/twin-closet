## Цены и лимиты (хватит с огромным запасом на $150)

| Модель | Цена | Лимит |
|---|---|---|
| `muse-spark-1.3` | $1.25 вход / $4.25 выход за 1M токенов; кэш входа $0.15 | 3000 запросов/мин |
| `muse-image-1.0` | **$0.01 за картинку** (`n` картинок = `n` × $0.01) | 150 запросов/мин |
| `sam-3.1` | фото $2.50 / 1000; **видео $0.20 / 1000 кадров**, минимум 50 кадров на запрос | 3000 запросов/мин |

- Картинка ~1280px ≈ 1300–1500 входных токенов у Spark. Точный счёт: `POST /v1/responses/input_tokens`.
- **Не используем Contributor mode** (`-contributor`): он дешевле, но разрешает Meta учиться на наших данных,
  а у нас фото тела пользователя.
- Ошибки 429/503 — повтор с экспоненциальной паузой и джиттером, уважать `Retry-After`.

## Файлы — `POST /v1/files`

- `purpose=user_data`, multipart; ответ `{ id: "file-…" }`, файл готов сразу.
- Инлайн (base64 / URL) — до 50 MB; через Files API — до 1 GiB. Командный лимит хранения 100 GiB.
- **Файлы не истекают сами** → при загрузке ставим `expires_after: { anchor: "created_at", seconds: 86400 }`
  (видео шкафа и тела нужны только на время обработки).
- Видео для SAM экспортировать с faststart: `ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`.

## SAM 3.1 — маски и треки (`POST /v1/responses`, `model: "sam-3.1"`)

Запрос — одно сообщение: `input_text` (что искать) + `input_image` (`image_url`) или `input_video`
(`video_url` или `file_id`). Видео: MP4/MOV, H.264/H.265/MPEG-4 (не WebM/VP9), до 15 000 кадров.

**Два вида подсказки, никогда вместе:**
1. **Понятие** — короткая фраза-существительное: `"t-shirt"`, `"jeans"`, `"sneakers"`.
   - **Одно понятие на запрос.** Списки через запятую дают 0 совпадений; `"and"` — только одно понятие.
   - Прилагательные сужают (`"red t-shirt"`), отрицания/«слева»/«или» работают плохо — фильтруем сами по рамкам.
   - Фото: все совпадения. **Видео: до 16 объектов на кадр.**
2. **Рамки и точки с нашими id** (до 16 объектов):
   `<0f>1<|box;x1=..;y1=..;x2=..;y2=..;w=W;h=H|>,2<|point;x=..;y=..;w=W;h=H|>-<|point;...|>`
   (`-` перед точкой = «это не объект»). Координаты — в пикселях исходника, `w/h` = размер медиа
   после поворота (EXIF!). Неверное соотношение сторон → 400. Хелпер: `buildObjectPrompt` из `@meta-sam/parser`.
   В видео подсказки можно ставить на разные кадры `<Nf>`, направление трека — `metadata.propagation_direction`
   (`both` по умолчанию / `forward` / `backward`).

**Ответ** — текст в `output_text`, по строке на кадр:
`<Nf>id<|box;x1;y1;x2;y2;w;h[;c]|><|mask;x=0;y=0[;c];data=H,W,~|!base85|>,id…`
- `id` стабилен через кадры (пока объект в кадре); кадры могут пропускаться и идти не по порядку — ключуем по `<Nf>`.
- Маска — растр **H×W меньше кадра** → растягиваем до `w×h` кадра.
- 0 совпадений = пустой `output_text`, это не ошибка.
- `metadata: { mask_encoding: "one_bit", include_confidence: "true" }` — маски в разы меньше + уверенность `c` 0..1.
- Стрим (`stream: true`) рекомендован для видео. Результаты слегка плавают между запусками.

**Парсер:** `npm i @meta-sam/parser` (сейчас 0.1.0; для `include_confidence` нужна ≥ 0.0.13):
`parseImageStream(events)` / `parseVideoStream(events)` → `.finalResult`, `recordsOfKind(records, "mask"|"box")`,
`decodeMaskToRaster(mask)` (Uint8Array 0/1, H*W, построчно), `decodeMaskToRLE` (COCO, для IoU), `decodeMaskToSVGPath`.

## Muse Spark — понимание фото/видео и JSON (`model: "muse-spark-1.3"`)

- Картинки: `input_image` с `image_url` (URL или `data:`) или `file_id`. **До 50 картинок в запросе**, до 50 MB каждая,
  jpeg/png/gif/webp.
- Видео: mp4, `input_video` (`video_url` / `file_id`) или `input_file` с `file_id`. Читает и звук
  (для звука в 1.3 качество хуже — если понадобится речь, `muse-spark-1.2`).
- **Рамки и точки:** просим в JSON, координаты в сетке **0–1000** от картинки, которую модель получила
  (`{"object_name", "bbox":[{"x_min","y_min","x_max","y_max"}]}`). Переводим в пиксели и отдаём SAM как box-подсказки.
- **JSON по схеме гарантирован** (декодирование ограничено схемой): в Responses API — `text.format`
  `{ type: "json_schema", name, schema, strict }`; в Chat Completions — `response_format`. Рекурсивные схемы → 400.
- Модель рассуждающая: `max_output_tokens` ≥ 4000, иначе ответ может прийти пустым (`length`);
  `reasoning.effort` — ниже для быстрых шагов (подписи), выше для образов.
- Кэш префикса удешевляет повторяющиеся системные промпты — держим их неизменными в начале запроса.

## Muse Image — примерка (`model: "muse-image-1.0"`)

Два входа:
- **`POST /v1/images/edits`** (совместим с OpenAI Images): `prompt` + `images: [{ image_url | file_id }]` (**1–10 картинок**),
  `n` 1–10, `size` (`"WxH"` задаёт только соотношение сторон — разрешение выбирает модель), `response_format` b64/url,
  `reasoning_strength` `low|high`, `output_format` webp/png/jpeg.
- **Responses API** — диалог: `input` из чередующихся `input_text`/`input_image` (подписываем каждую картинку текстом
  перед ней), ответ — `image_generation_call` с base64 в `result`; следующий шаг через `previous_response_id`
  («тот же образ, теперь вид сбоку») — **это наш путь к одинаковой вещи на 4 ракурсах.**

Важно для нас:
- **Маски нет**: `mask`, `input_fidelity`, `partial_images` → 400. Поэтому лицо/руки защищаем вклейкой (PLAN.md, 3.1).
- **Модель сама ищет референсы в интернете** (картинки и факты). Для примерки **выключаем**:
  инструмент `image_generation` с `enable_image_search: false`, `enable_web_search: false`, `enable_shell: false`
  (в images-эндпоинтах — `tool_enablement`). Иначе может подтянуть чужие фото вместо наших вещей.
- Разрешение ответа ≠ запрошенному → выравнивание с оригиналом обязательно.
- Блок по безопасности → 400 `content_policy_violation`; 503 — повторить.

## Решения, которые из этого следуют

1. **Скан шкафа без «одно понятие на запрос»:** Muse Spark смотрит несколько ключевых кадров видео и возвращает
   список вещей с рамками (0–1000) → переводим в пиксели → **один** запрос SAM с box-подсказками до 16 вещей,
   трек через всё видео. Больше 16 — делим на группы. Запасной путь — понятия по одному (`"t-shirt"`, `"jeans"`…).
2. **Лучший кадр вещи** — по треку SAM: самая большая и резкая маска, не обрезанная краем кадра.
3. **Скан себя** — SAM понятиями на 4 выбранных кадрах: `"person"`, `"face"`, `"hair"`, `"hand"`,
   `"t-shirt"`/`"pants"`/`"shoes"` (по тому, что Spark увидел на тебе).
4. **Примерка** — Responses API Muse Image с выключенным поиском, подписанные входные картинки
   («photo of me», «garment 1: jeans from store», «garment 2: my black hoodie»), `n` = 3–4 → выравнивание →
   вклейка → проверка Spark'ом → остальные ракурсы через `previous_response_id`.
5. **Деньги**: даже 1000 примерок по 4 варианта = $40. Можно не экономить на вариантах — экономим только время.

## Что уже в коде (27.10, без ключа)

- `server/src/meta.ts` — клиент на fetch: повторы при 429/503 по Retry-After, файлы с удалением через сутки,
  разбор ответа (текст, цитаты, картинки).
- `server/src/models/spark.ts` — промпты и строгие JSON-схемы всех шагов Muse Spark: вещи на кадрах шкафа (рамки 0–1000),
  подписи, дубли, 4 ракурса, бирка и ценник (REF, цена, старая цена), «у тебя уже есть», 3 образа, проверка примерки,
  поиск вещи в магазине и «идёт ли распродажа» (веб-поиск с `user_location`).
- `server/src/models/sam.ts` — подсказки-понятия и рамки/точки с нашими id, тело запроса (one_bit + уверенность),
  разбор ответа и растры масок — официальным `@meta-sam/parser` 0.1.0 (с 28.10): `buildObjectPrompt`, `parseImageStream` /
  `parseVideoStream`, `decodeMaskToRaster`; `samMask` растягивает маску из рамки во весь кадр для склейки примерки.
  Проверено на настоящем ответе SAM 3.1 из README пакета. Рамка в подсказке — правая и нижняя граница не включительно.
- `server/src/models/image.ts` — запрос примерки Muse Image (подписанные картинки, поиск выключен) и следующие ракурсы
  через `previous_response_id`.
- `server/src/models/twin.ts` — системный промпт Twin и инструменты (шкаф, вишлист, магазины, поиск, вишлист, примерка).
- Подключено к задачам: поиск вещи в магазине (`product_lookup`) и ежедневная проверка распродажи.
- Тесты `server/test/models.test.ts` — схемы, формат подсказок SAM, разбор, повторы, поиск в магазине с подставным API.

- 29.10 (без ключа): все шаги задач подключены к моделям — `server/src/pipeline/` (item, closet, body, tryon, twin, looks),
  проверены на подставном API `server/test/fake-meta.ts` (SAM — настоящий ответ из README парсера). Twin крутит цикл
  `function_call` → `function_call_output` (до 6 раундов), «сохранить» и «примерить» возвращает приложению кнопками.
