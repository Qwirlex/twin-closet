# Twin Closet — план на хакатон Meta

Приложение на телефон: сканируешь себя и свой шкаф, кидаешь скриншот вещи из любого магазина —
видишь, есть ли у тебя уже похожее, и как новая вещь смотрится на тебе вместе с твоими вещами.

**Сроки.** Старт 26 октября. Сдать до 4 ноября 21:00 по Нью-Йорку = **5 ноября 02:00 по Дублину**.
Сдаём заранее, 4 ноября вечером. Призы: Indie, первое место $150 000.

**Как судят готовый проект:** польза 30%, использование моделей Meta 25%, демо и видео 25%, техника 20%.
Значит: каждая модель Meta должна делать заметную работу, а демо-видео должно быть идеальным.

## 1. Что видит человек (4 экрана)

1. **«Отсканируй себя»** — встаёшь в полный рост, телефон на полке, 6 секунд медленно поворачиваешься.
   Через минуту — 4 твоих фото: спереди, 3/4, сбоку, сзади.
2. **«Отсканируй шкаф»** — два режима:
   - *Вешалка*: ведёшь камерой вдоль шкафа;
   - *По одной*: показываешь вещи в камеру по очереди (надёжнее, им же снимаем демо).
   Через пару минут — сетка твоих вещей, вырезанных без фона, с подписями «чёрное худи, хлопок, oversize».
3. **«Примерь»** — три способа добавить новую вещь:
   - скриншот (или «Поделиться → Twin Closet» прямо из Instagram/магазина);
   - **скан в магазине**: снимаешь вещь на вешалке или полке фото/коротким видео, плюс ценник и бирку —
     приложение вырезает вещь, читает цену, размер, состав и бренд;
   - ссылка на товар.
   Сразу: «У тебя уже есть 2 похожих» с картинками. Ниже — 3 образа «новая вещь + твои вещи»,
   каждый можно открыть **на тебе** с 4 сторон. Можно добавить второй скриншот из другого магазина.
4. **Решение** — «Купить» (ссылка в магазин), «Не нужно», «Сохранить образ».
   Бонус, если успеем: «Не носишь это полгода → выставить на продажу».

Вокруг этого:
- **Гайд при первом запуске** — 3 шага (скан себя → скан шкафа → примеряй что угодно), Skip / Continue.
- **Вход** — Apple, Google, почта (Supabase Auth); строка о приватности: скан и фото видны только тебе, удалить в Me.
- **Twin — ИИ-стилист** (чат, кнопка-сфера в шапке «Шкафа»): объясняет, что делать дальше и как снимать,
  собирает образы под повод («ужин в пятницу») из шкафа + вещей, которые ты присматриваешь, и сразу
  предлагает «Try it on». Голосом — через микрофон.

## 1.1. Вишлист и любимые магазины (идея 27.10)

Человек отмечает любимые магазины (Zara, Bershka, Pull & Bear…) и складывает вещи в вишлист.
Twin, собирая образ «на ужин в пятницу», берёт вещи из шкафа и добавляет: «к этому подойдёт вещь из твоего
вишлиста» или «могу поискать в твоих магазинах» — и предлагает 1–3 вещи купить, сразу с примеркой.

- **Магазины.** Выбираешь регион — видишь, какие магазины там есть; но регион только подсказывает:
  поиск идёт по всем брендам (люди путешествуют и заказывают из других стран). Подписка на магазин = он
  участвует в поиске Twin. Можно добавить любой магазин по адресу сайта.
- **База магазинов** — открытый набор Name Suggestion Index (проект OpenStreetMap, лицензия BSD-3):
  1083 бренда одежды с Wikidata и странами. 238 работают по всему миру (Zara, H&M, Uniqlo, COS…),
  остальные — региональные (Ирландия — 23, Украина — 13, Британия — 87). В приложение берём 60 популярных,
  официальные сайты вписываем вручную (в наборе их нет).
  Если нужно точнее «есть ли Zara в этой стране» — разово считаем магазины бренда по стране из OpenStreetMap (Overpass).
- **Живые магазины в первой версии — Zara, Bershka, Pull & Bear** (одинаковая бирка с артикулом REF).
  Остальные бренды можно отметить, но у них «Coming soon», внизу списка — «Other shops coming soon».
- **Поиск вещей** — Muse Spark с `web_search` (Responses API) по сайту магазина + `user_location` (страна):
  по REF с бирки или по описанию находит ту же вещь онлайн — ссылка, цена. Ещё одна заметная работа модели Meta.
  Сайты и внутренние API магазинов напрямую не трогаем: их правила запрещают роботов, сайты закрыты защитой.
  Данные вещи — из фото человека (вырезка SAM, бирка читает Spark) и из найденного Spark.
- **Скидки:** сервер раз в сутки проверяет цены вещей из вишлиста (тем же поиском Spark); если дешевле —
  в вишлисте бейдж «−20%» и зачёркнутая цена. Пуш-уведомления — потом.
- **Вишлист** — сердечко на любой вещи: из скриншота, ссылки, скана в магазине, ответа Twin, поиска.
  Вещь из вишлиста можно примерить и сравнить со шкафом («у тебя уже есть похожее»).
- **Twin получает инструменты:** шкаф, вишлист, любимые магазины, поиск в магазинах, добавить в вишлист, примерить.

Спека: [docs/spec-stores-wishlist.md](docs/spec-stores-wishlist.md). Экраны, данные магазинов и слежка за ценой — без ключа
(делаем сразу); поиск через Spark и Twin — с ключом.
В порядке «что режем» — после голоса в Twin, но до режима «вешалка».

## 1.2. Размер, посадка, стиль, больше магазинов (идеи 28.10)

Главное из всего — **посадка**. Вещь твоего размера может не сесть: джинсы впору в талии, но тесные в бёдрах
или длиннее на 5 см. Без этого примерка — красивая картинка, а не ответ «брать или нет».

### А. Параметры тела — только по желанию
- При входе (и потом в Me) — экран «Твои параметры», его можно пропустить: рост, вес; по желанию обхваты
  (грудь, талия, бёдра), длина ноги по внутреннему шву, размер обуви. Как мерить — картинкой.
- Проще для человека: ввёл только рост — остальное оценивает Muse Spark по скану себя (4 ракурса, рост даёт масштаб).
  Человек видит цифры и может поправить; честно пишем «оценка ±2–3 см».
- Хранится только у человека (Supabase, RLS: новые поля в `profiles`), удаляется в Me.
- Нужны для: размера в каждом магазине (Б), посадки (В), есть ли твой размер в наличии (Г).

### Б. «Мой размер» — только если сам попросил
- В Me переключатель «Показывать мой размер», по умолчанию выключен. Пока выключен — нигде нет S/M/L и цифр,
  только «сядет / будет тесно в бёдрах». Кому-то это неприятно — не навязываем.
- Включил — «Твой размер: Zara M, Bershka S»: у брендов разные таблицы. Таблицу размеров вещи находит
  Muse Spark поиском по странице товара.

### В. Посадка — самое важное
Размер не отвечает на вопрос «сядет ли». Делаем **карту посадки** по зонам: плечи и грудь, талия, бёдра,
длина, рукав, длина по шву.
1. **Замеры вещи** (см, для каждого размера):
   - со страницы товара — у многих магазинов есть таблица замеров (Muse Spark `web_search`);
   - тип посадки (slim / regular / relaxed / oversize) — Spark читает с бирки и из описания;
   - вещь из шкафа: «положи на пол рядом с листом A4» → SAM 3.1 вырезает вещь, лист даёт масштаб →
     ширина, длина, ширина штанины.
2. **Запас по каждой зоне** = замер вещи − замер тела. По запасу и типу посадки: «впритык / по фигуре /
   свободно / oversize» и предупреждения: «в бёдрах будет тесно», «длина +4 см — соберётся у стопы».
3. **Сравнение с любимой вещью** — самый надёжный способ, так работают сервисы подбора размера.
   Отмечаешь в шкафу «эти джинсы сидят идеально» → новая вещь сравнивается с ними: «на 2 см шире в бёдрах,
   на 3 см длиннее». Свои обхваты знать не нужно.
4. **Видно на примерке.** Запас по зонам идёт в промпт Muse Image (как именно сидит: «свободно в бёдрах,
   до щиколотки со сборкой»), поверх рендера — метки по зонам (зелёная / жёлтая / красная). Muse Spark проверяет,
   что посадка на картинке совпадает с расчётом.
5. **Учимся на отзывах:** после покупки «как села?» — запоминаем поправку бренда («маломерит в бёдрах»).
6. **Пропорции, а не один размер (главная фишка, 28.10).** Фигура — это соотношения зон, а не буква: широкие бёдра
   при тонкой талии не значат «XL» и полноту. Поэтому:
   - посадку считаем по каждой зоне отдельно и ярлык на всё тело не вешаем никогда — ни человеку, ни в подписях;
   - видим пропорции (талия : бёдра, плечи : бёдра, длина ноги) и под них советуем **крой**, а не размер побольше:
     «в талии тебе M; в бёдрах эта модель узкая — возьми relaxed / curve fit или вещь со стрейчем (есть в составе)»;
   - если ни один размер этой модели не садится сразу на талию и бёдра — честно говорим это и предлагаем
     похожую вещь с другим кроем (из магазинов, вишлиста, Twin), а не «бери XL и ушивай»;
   - тянется ли ткань — Spark читает состав с бирки или страницы (эластан, трикотаж), запас для стрейча меньше.
- Честно: настоящая физика ткани (3D-манекен и симуляция драпировки, как в CLO3D) за неделю невозможна и требует
  3D-лекал вещи. Наш путь — замеры, запас, сравнение с любимой вещью и метки на примерке: реально и понятно.
- До сдачи: п. 1–4 для джинсов/брюк и верха (там промахи чаще всего). Отзывы — потом.

### Г. Онлайн-магазины, включая дешёвые
- Кроме Zara, Bershka, Pull & Bear: ASOS, Zalando, H&M, Shein, AliExpress, Temu.
- Так же, как сейчас: только Muse Spark `web_search` (ссылка, цена, замеры), без роботов на сайтах.
- В дешёвом сегменте размеры часто маломерят и сильно разные → карта посадки (В) там важнее всего,
  в карточке: «по их таблице тебе нужен L».
- Наличие размера: Spark ищет его на странице; часто без браузера его не видно → честно «проверь наличие» со ссылкой.

### Д. Модно, а не базово
- Раз в неделю сервер просит Muse Spark (`web_search`) собрать «что сейчас носят» для страны и сезона:
  силуэты, цвета, сочетания, вещи сезона. Одна выжимка на всех, в кэше.
- Сборка образов получает стиль человека (Е) + выжимку трендов + правило: без скучной базы, если не просили
  («белая футболка + синие джинсы»), в каждом образе хотя бы одна живая деталь — силуэт, слои, акцент, фактура.

### Е. Стиль человека
- **Опрос** при входе (по желанию, ~30 с): карточки образов разных стилей — нравится / нет. Стили: old money /
  quiet luxury, минимализм, streetwear, спорт-шик, gorpcore, y2k, бохо, смарт-кэжуал, techwear, романтичный…
- **Свои фото образов** (галерея, скриншоты из Pinterest) → Muse Spark определяет стиль, цвета, силуэты.
- **Шкаф** — что человек реально носит, тоже подсказка.
- Итог — **профиль стиля**: 2–3 главных стиля с весами, любимые цвета, чего избегает. Виден в Me, можно поправить.
- «Научить ИИ стилям»: дообучать модель не нужно и некогда. Даём Muse Spark справочник стилей (силуэты, вещи,
  ткани, цвета каждого) — он применяет его к фото. Открытые наборы для сверки: Fashionpedia (CC BY 4.0, атрибуты
  одежды); DeepFashion и Polyvore — только для исследований, в продукт не берём.
- Twin и образы не предлагают то, что против стиля (old money ≠ спортивки с батником), если человек сам не попросил.

### Ж. Скан шкафа: быстро, но без потери деталей
Для каждой вещи нужны перед, зад, бок и детали (принт, пуговицы, лого, фактура) — иначе примерка сзади и сбоку
выдумывает.
- Режим «по одной» — короткое видео 3–5 с на вещь: показал перед → повернул → зад (можно на вешалке).
  SAM 3.1 ведёт вещь по видео, Muse Spark выбирает лучший кадр каждой стороны и 1–2 крупных кадра деталей.
- Быстро и дёшево: до моделей отбрасываем смазанные и одинаковые кадры (резкость считаем сами, бесплатно);
  моделям уходят 3–5 лучших кадров на вещь, а не всё видео.
- Качество: не видно сторону или кадр смазан — просим переснять только эту вещь («покажи спину худи»).
- «Вешалка» — быстрый обзор: находит вещи и предлагает доснять «по одной» те, где не хватает сторон.
- Примерка с 4 сторон берёт настоящий вид вещи сзади и сбоку.

### З. В магазине: бирка + вещь → с моим шкафом
- Фото бирки (Spark читает REF, размер, цену, состав) + фото **или короткое видео** вещи. Видео даже лучше:
  тем же пайплайном «по одной» сразу все стороны.
- По REF Spark находит страницу товара → таблицу замеров → посадку в твоём размере (В).
- Дальше: «у тебя уже есть похожее», 3 образа со шкафом, примерка с 4 сторон с картой посадки, сердечко в вишлист
  и слежка за скидкой.

## 1.3. Сайт = приложение, и путь судьи с ПК (решение 28.10)

iPhone закрываем сайтом (TestFlight за $99 — нет). Сайт должен работать как приложение: всё, кроме
«Поделиться → Twin Closet» (этого iPhone сайтам не даёт). Главный вопрос — **как судья проверит сканы с ПК**.

**Путь судьи с ПК:**
1. Открыл сайт → «Explore the demo account»: шкаф, скан себя и образы уже есть — примерка работает сразу.
2. Новая вещь: скриншот с любого сайта магазина — перетащить на страницу или выбрать файл.
3. Сканы шкафа и себя — два способа:
   - **«Продолжить на телефоне»**: на ПК QR → судья сканирует своим телефоном → тот же шкаф открывается на телефоне
     (сайт, ставить ничего не надо) → снимает видео → вещи сами появляются на ПК через несколько секунд;
   - **«Use sample video»** — готовые видео, без камеры вообще (нужны настоящие видео и ключ Meta).

**Что делаем:**
- **Данные не теряются.** Сейчас на телефоне настройки живут в памяти до перезапуска (гайд снова, вишлист пропадает,
  новый id устройства), а свои вещи не сохраняются нигде. Телефон — `expo-sqlite/kv-store` (синхронно), сайт — localStorage;
  шкаф, примерка, сохранённые образы — туда же.
- **Синхронизация по id устройства:** сервер хранит состояние устройства (шкаф, примерка, образы; не больше 256 KB,
  7 дней без обновлений — стирается). Приложение отправляет изменения и подтягивает чужие — так ПК видит вещи с телефона.
- **«Продолжить на телефоне»:** QR со ссылкой `twin-closet.vercel.app/pair?d=<id>`. Телефон спрашивает «Подключить к
  компьютеру?» и берёт тот же id. Id становится ключом доступа — делаем его криптостойким (не Math.random).
  Кнопки: на экране скана на ПК («Scan with your phone») и в Me.
- **Как приложение на iPhone:** «На экран Домой» — иконка, название, полный экран без панели Safari, тёмная строка
  статуса, отступы под вырез экрана.
- **Камера со страницы:** на телефоне «Record» открывает камеру (видео и фото); на ПК — выбор файла и перетаскивание.
- **Проверка:** пройти каждый экран на сайте в размере iPhone и на ПК, всё, что ведёт себя не как в приложении, — в список и чинить.
- После правок — пересобрать APK (текущая сборка без сохранения данных).
- **Баг 28.10 (iPhone, сайт на экране «Домой») — исправлен 28.10:** шапка уходила под часы — Expo Router на вебе отдаёт
  нулевые отступы, теперь их меряет свой SafeAreaProvider; чёрная полоса внизу — `height: 100%` в режиме «на экран Домой»,
  там теперь `100vh`. Заодно: вкладки Шкаф / Образы / Примерить / Я на вебе не листались (TabSlot не сжимался) — низ
  экрана был недоступен и на ноутбуке судьи. Проверено на эмуляции: ноутбук 1440×900, 1366×657, 1280×600, iPhone SE / 15 /
  Pro Max с вырезом, Android — все 13 экранов листаются до последней кнопки. Осталось: глянуть на настоящем iPhone.

## 2. Какие модели Meta что делают

| Шаг | Модель | Что делает |
|---|---|---|
| Скан шкафа | **SAM 3.1** (видео) | находит каждую вещь по текстовым подсказкам («t-shirt», «jeans», «jacket»…), ведёт через кадры, одна вещь = один трек |

## 3.1. Как сделать, чтобы лицо, руки и фигура не менялись

У Muse Image нет параметра «маска»: модель перерисовывает картинку целиком, и в своём разрешении
(документация API: в edits только image/prompt/size/n). Поэтому защиту делаем сами — **меняется только
одежда, всё остальное остаётся твоими настоящими пикселями по построению**, а не «по просьбе модели».

1. **Маски до генерации (SAM 3.1 на твоём фото):** «face», «hair», «hands», «person», плюс текущая одежда:
   «t-shirt», «jeans», «shoes»… Из них две зоны:
   - **защищённая** — лицо, волосы, кисти рук (и всё, что не человек: фон, пол);
   - **зона одежды** — где сейчас твоя одежда.
2. **Генерация:** Muse Image получает твоё фото + вырезки вещей и строгий промпт: та же поза, тот же кадр,
   поменять только одежду. Просим `n = 3–4` варианта сразу.
3. **Выравнивание:** модель отдаёт картинку в своём разрешении и может чуть сдвинуть фигуру.
   SAM находит «person» на результате, сравниваем с маской на оригинале и подгоняем масштаб и сдвиг.
   Если фигура уехала сильно (маски совпадают меньше чем на ~92%) — вариант выбрасываем.
4. **Вклейка обратно (главное):** итог = **оригинальное фото везде**, кроме зоны одежды, где берём
   сгенерированные пиксели. Зона одежды = старая одежда ∪ новая одежда (SAM на результате),
   **минус защищённая зона** — лицо, волосы и кисти всегда из оригинала. Края смягчаем на 4–8 пикселей.
   - Длинная куртка вместо футболки → зона растёт вниз и на руки, рукава закрывают руки — правильно.
   - Майка вместо рубашки → открываются плечи и руки: эти пиксели берём из генерации, кисти — из оригинала.
   - Головной убор или перчатки — единственный случай, когда защищённую зону частично снимаем.
5. **Свет и цвет на стыке:** подгоняем яркость и цвет вставки к оригиналу по полосе вдоль края
   (простой перенос среднего и разброса цвета), чтобы не было «наклейки».
6. **Автопроверка:** Muse Spark смотрит «оригинал + результат + вещь» и отвечает JSON: тот же человек,
   поза не изменилась, вещь совпадает с образцом (цвет, принт, длина), шов незаметен. Лучший из `n` вариантов
   уходит пользователю; если все плохие — ещё одна попытка, потом честное «не получилось с этой фотки».
7. **Ракурсы:** первый удачный рендер (спереди) идёт образцом в промпт для остальных трёх ракурсов, чтобы
   вещь выглядела одинаково со всех сторон.

Итог: лицо, волосы, руки и фон **не могут** измениться — они физически из твоего фото.

**Готово 27.10 (без ключа):** `server/src/tryon/compose.ts` — выравнивание по силуэту и открытому телу, зона одежды,
вклейка с мягким краем, перенос цвета по полосе (без лица — его модель могла изменить), отказ при другой позе
(сравнение тела вне одежды на обоих снимках: куртка на голые руки — не «другая поза»). Тесты на синтетике
(`server/test/compose.test.ts`) и проверка на настоящих фото (`npm run demo:compose -w @twin/server`).
С ключом остаётся подставить маски SAM 3.1 и варианты Muse Image.
Меняться может только то, что под одеждой, — и это ровно то, что мы хотим.

### Путь судьи в веб-версии (снимать ничего не нужно)

Судья смотрит с ноутбука, камеры и шкафа у него под рукой нет. Поэтому каждый шаг, где в приложении нужна
съёмка, в вебе можно пройти тремя способами:

| Шаг | Снять | Загрузить своё | Готовое |
|---|---|---|---|
| Скан шкафа | видео с камеры телефона (в мобильном браузере тоже) | своё видео шкафа | **«Use sample video»** — наше видео шкафа, SAM 3.1 и Spark обрабатывают его на глазах |

| Новая вещь | фото в магазине | **любой скриншот из магазина** — главный шаг для судьи | 2 вещи уже в примерке |

1. Ссылка открывается сразу в демо-аккаунте: шкаф и скан тела загружены — судья видит всё за 5 секунд.
2. Главное судья проверяет **своей** вещью: кидает скриншот → вырезка SAM → «у тебя уже есть похожее» от Spark →

3. В скане шкафа и себя — кнопки «Record», «Upload» и «Use sample video»: модели работают вживую, прогресс по шагам.
4. Чтобы судьи не сожгли кредиты: готовые видео считаем один раз и кэшируем, свои загрузки — лимит на сессию.
